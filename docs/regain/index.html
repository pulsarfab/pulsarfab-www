regain documentation

Regain control of your equipment.

Native astronomy drivers, resilient camera capture, and one familiar setup experience across NINA, Windows ASCOM, and Alpaca.

PulsarFab regain, formerly ZWOgain, connects your existing equipment using Rust drivers and matching setup tools. The camera SDK runs in a separate process, so a stuck SDK does not take down your imaging application. Accessory drivers talk directly to USB or serial without a vendor SDK.

What do you want to do?

Keep NINA or Alpaca captures running

Retry a failed download before repeating an exposure, reconnect with camera and cooler settings restored, and keep a completed image even if cleanup fails. Native NINA, ASCOM, and Alpaca use the same Rust recovery engine. Choose your retry policy →

Harden USB transfers without the camera SDK

Supported Direct USB drivers bound whole-frame reads, drain cancellations, reject partial images, and can reread retained frames. Windows ASI2600 P25 recovery can also reopen the USB handle and verify earlier pixel chunks. Direct USB behavior and limits →

Put the whole rig on a small headless computer

One Alpaca server exposes supported cameras, rotators, filter wheels, focusers, and an OFP2 flat panel. Configure devices in a browser and connect over your LAN; Rust workers isolate device access. Set up a headless host →

Connect more than two ASCOM cameras

Four independent camera entries let a main camera, guider, and second imaging train keep separate serial selections and recovery settings. Both 32-bit and 64-bit clients are supported. Configure camera slots →

Keep the ASCOM side small

A thin .NET COM adapter delegates camera capture and recovery to local Rust workers over private pipes. No HTTP server or vendor control application is required. How the local driver runs →

NINA and native ASCOM run on Windows x64. Rust workers and the Alpaca server build on Windows, Linux, and macOS. Linux/macOS USB hardware validation remains incomplete; successful simulator tests are not physical device validation.

One device, one owner

Disconnect other controllers before opening a device. FocusCube3 ASCOM clients share one local server, but native NINA, ASCOM, Alpaca, and Pegasus Unity cannot all own the serial port at once. Use the ASCOM driver inside NINA when sharing with other ASCOM clients.

Open implementation

Code and regain artwork use Apache-2.0. Bundled third-party components retain their own licenses. PulsarFab regain is an independent project and is not affiliated with or supported by ZWO. Protocol notes and hardware evidence live in the source documentation.
